# ADR 0003：每个招聘批次手动维护一个投递进度

状态：已接受

日期：2026-08-26

项目所有者通常只会在一家公司的一个招聘批次中投递一到两个岗位，实际管理目标是快速标记“这个批次进行到哪里”，而不是维护每个岗位的完整状态。项目决定让 `ApplicationProgress` 归属于 `RecruitmentBatch`，每个批次只有一个由用户手动选择的进度；系统不根据岗位数量、最远阶段或其他岗位状态自动计算。该决定取代 ADR 0002 中“投递进度归属于岗位”的部分，但保留招聘批次组织多个招聘岗位的领域结构。

## Considered Options

- 岗位级进度：信息最精确，但会增加录入负担，不符合当前个人使用习惯。
- 批次级自动汇总：表面简单，但必须定义多个岗位状态冲突时的优先级，仍然过度设计。
- 批次级手动进度：采用；一行一个状态，由用户自行决定最能代表当前求职情况的值。

## Consequences

同一家公司不同招聘批次仍是不同记录，但不为少见的同时投递多个批次场景增加自动规则。已有岗位级进度迁移到批次时，只有一个批次对应零个或一个进度记录才能自动迁移；同一批次存在多个岗位进度时必须中止并由用户决定，禁止猜测或静默丢弃。
