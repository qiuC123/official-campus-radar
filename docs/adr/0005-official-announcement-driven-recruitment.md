# ADR 0005：以官方招聘公告驱动招聘批次，官网优先、微信回退

状态：主要公告来源规则已由 ADR 0009 取代，“公告与投递地址不得复用”的限制已由 ADR 0006 取代

日期：2026-08-30

项目只让具有合格官方招聘公告的当前招聘批次进入正式页面。主要公告优先采用企业官网或官方招聘系统的正式通知；官网没有合格公告时，才采用经 `wechat-oa` 回读并完成企业身份核验的微信公众号文章或微信小程序通知。招聘雷达负责官网检索、企业与批次判断、岗位和申请渠道，`wechat-oa` 只负责微信公众号候选回读与文章证据。该决策取代 ADR 0001 中“岗位接口可以独立驱动正式数据”的部分，但保留官网、ATS 和 API 作为具体岗位的首选来源。

## Consequences

- 招聘公告、岗位来源和投递入口是三个独立概念；一个主要公告只归属一个招聘批次，同一批次也只展示一个主要公告，且投递入口不得回退复用公告地址。
- 同一个真实岗位门户可以承载多个招聘批次，门户 URL 因而不能充当批次唯一身份；结构化接口必须使用项目编号等稳定字段做互斥且完整的分区。分区只能创建内部候选投影，不能替代“一批次一公告”的正式准入证据。
- 集团官网公告可以使用不参与岗位抓取的“官网公告源”；具体岗位仍优先从官网、ATS 或 API 获取。
- 搜索标题和摘要只是公告候选；必须重新读取官方原文并核验身份后才能成为主要公告。
- 官网核验先用普通 HTTP；只有显式允许时才在隔离无痕浏览器中渲染动态页面。两者都失败时只能使用带文件哈希和人工确认标记的本地快照，且不得把快照核验伪装成实时回读。
- 春招、明确重新开启的春招补录、秋招和专项计划可以作为不同批次并行存在；单纯延期或更正仍属于原批次。同一页面明确列出多个项目或岗位池时，必须先按项目区块拆出独立公告身份再分别准入，不自动复用或合并。
- 招聘对象只能来自主要公告的明确证据，不能按当前年份或岗位文字推断。
- 没有稳定网页 URL 的投递小程序保存名称、路径和打开说明，页面显示非链接式投递提示；它仍不得复用公告地址。
- 图片型微信公告在 OCR 和人工确认完成前保持待核验；即使 `wechat-oa` 返回 OCR 或二维码证据，也不能把未经确认的图片文字当成已核验正文。
- 招聘雷达保存 `wechat-oa` 已观察到的外链和图片媒体证据，但只把它们列为待核验申请渠道候选；不会自动打开二维码载荷或直接生成投递入口。
- 从旧名单迁移时先生成预演报告，公告门控默认关闭；只有人工确认预演摘要后才允许一次性开启，避免未审查就隐藏现有企业。本地项目已按确认过的摘要完成首次切换；后续新批次默认仍受同一公告门控约束。
