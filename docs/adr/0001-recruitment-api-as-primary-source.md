# ADR 0001：以企业招聘官网接口为主数据源，微信公众号降级为发现渠道

状态：已接受

日期：2026-08-20

影响范围：数据来源策略、采集适配器、证据模型、更新自动化程度

## 背景

Phase 01 交付了本地离线骨架，但零真实数据：`data/source_catalog.csv` 只有表头，全部业务表 0 行。原设计假定的采集路线是「企业官网招聘页 HTML + 逐字段 CSS selector 证据」，该路线在启用真实来源时暴露两个阻断：

1. `HtmlSourceAdapter.validate_source_config` 要求每个来源配置 10 个必填 selector 与稳定的公告/岗位身份标识。按目标规模（对标参考站点近三天 291 家企业）需维护数百套 selector，且官网改版即失效，单人项目不可持续。
2. `radar/collectors/html.py` 中 `positions=(PositionCandidate(...),)` 硬编码单岗位，无法承载一则公告下数十个岗位。

同期用户提出：企业招聘信息主要发布在微信公众号，主张只采集该渠道。

## 实测证据

以下均为 2026-08-20 免登录实测结果。

微信公众号文章（2 篇样本，均为纯图片正文）：

| 样本 | 正文纯文本长度 | 图片数 | 岗位信息 | 官方入口链接 |
| --- | --- | --- | --- | --- |
| 双胞胎集团 2027 届校招 | 0 | 7 | 全在图片内 | 无（在图片内） |
| 腾讯 青云计划 2027 校招 | 0 | 4 | 文章未列岗位 | `join.qq.com/qingyun.html?...` 可提取 |

微信文章可稳定提取的字段（全平台 DOM 结构统一，一套解析器通用）：`#activity-name` 标题、`#js_name` 公众号名、JS 变量 `biz` / `user_name`（如 `gh_88b080670a71`，永久身份标识）、JS 变量 `create_time`（Unix 时间戳，DOM 内 `#publish_time` 在服务端响应中为空）、正文外链。

企业招聘官网可达性（8 个目标）：

| 目标 | 结果 | 结论 |
| --- | --- | --- |
| 腾讯 `careers.tencent.com/tencentcareer/api/post/Query` | HTTP 200，免登录，2276 个岗位，字段完整（见下表）。但工作经验分布为三年以上 68 / 五年以上 46 / 两年以上 47 / 不限 8，**该接口是社招池**；`attrId=3` 的 85 条为海外实习且混有 2025 年旧数据 | 接口形态与免登录可达性已验证；**国内校招岗位不在此接口** |
| 阿里 `talent.alibaba.com` | SPA 空壳，可见文字 10 字 | 必有 JSON 接口，路径待抓包 |
| 字节跳动 `jobs.bytedance.com` | SPA，HTML 794 KB，可见文字 22 字 | 必有 JSON 接口，路径待抓包 |
| 美团 `zhaopin.meituan.com` | SPA，接口线索 `/api/category/allData` | 必有 JSON 接口，路径待抓包 |
| 华为 `career.huawei.com/.../campus-recruitment.html` | 可见文字 2387 字**全为 Vue 模板占位符**（`{{item.jobArea}}`、`{{jobRecommendData.pageVO.totalRows}}`），非真实岗位 | 同为前端渲染；模板变量暴露 `pageVO` 分页结构 |

| 国家大学生就业服务平台 `job.ncss.cn` | 计数接口免登录返回 309166；岗位列表接口 `POST /student/jobs/jobslist` 返回登录页 | 需登录，放弃 |

腾讯接口单个岗位对象的完整字段（用于适配器字段映射参考）：

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `PostId` | 稳定唯一 ID，如 `2034975730101809152` | 岗位身份键 |
| `RecruitPostName` | 岗位名称 | 岗位标题 |
| `LocationName` / `CountryName` | 城市 / 国家 | 地点归一化 |
| `CategoryName` / `BGName` / `ProductName` | 职类 / 事业群 / 产品线 | 分类 |
| `Responsibility` | 岗位职责全文 | 原文摘录 |
| `LastUpdateTime` | 更新时间，中文格式 `2026年08月20日` | 需解析 |
| `PostURL` | 岗位详情页 URL | 官方原文链接 |

| `RequireWorkYearsName` | 经验要求，如 `三年以上工作经验` / `不限` | **区分校招与社招的关键信号** |

接口参数：`pageSize` 实测可开至 200；`attrId` 为岗位属性（1=社招主池 2167 条，3=实习 85 条，5=研究类 7 条）；响应结构 `{"Code":200,"Data":{"Count":N,"Posts":[...]}}`。

## 决策

采用两级解耦架构。

**第一级 · 岗位层（主数据源，全自动）**：企业招聘官网的 JSON 接口。每天定时全量/增量同步，无需人工干预。

实测的 7 个企业招聘站点**全部为前端渲染**，无一可直接从 HTML 取得岗位（华为曾被误判为服务端渲染，实为未渲染的 Vue 模板）。因此适配器以 JSON 接口为唯一主形态；服务端渲染页面适配器暂不需要，待出现真实案例再加。

### 接口发现方法与成本

SPA 必然调用接口，故接口一定存在且通常免登录（腾讯已验证）。但**接口路径无法通过静态分析可靠获得**：`careers.tencent.com/campus.html` 静态 HTML 仅 1896 字节且不含任何 `<script>` 标签（脚本动态注入），`join.qq.com` 的 CDN bundle 对非浏览器请求返回空响应，按常见命名猜测的端点全部 404。

确定接口路径需一次人工抓包：浏览器打开目标企业校招岗位列表页 → F12 → Network → 筛选 XHR/Fetch → 找到返回岗位列表的请求 → 记录 URL、请求方法、参数、响应中列表与字段的 JSON 路径。单家企业约 3~5 分钟，**一次性动作**，之后由适配器配置驱动，长期自动运行。

### 校招与社招常为两套独立系统

腾讯社招在 `careers.tencent.com`，国内校招在 `join.qq.com`（独立域名、独立 CDN 路径 `campusjoin/`、独立页面 `qingyun.html`），两者接口不通用。因此接口发现必须明确针对**校招系统**，取得任一招聘接口即认定完成是错误的。适配器接入时须以 `RequireWorkYearsName`（或同类经验字段）等信号交叉验证所取数据确为校招/实习岗位。

**第二级 · 发现层（补充，半人工，低频）**：微信公众号文章。仅用于发现名单外的企业、确认校招启动时间点、获取官方入口 URL 作为准入证据。由用户手动粘贴文章链接触发，单篇页面免登录公开可访问。

企业名单由用户一次性提供，之后通过批量探测识别各企业所用招聘系统：自建接口单独写适配器；通用 ATS（Moka、北森、智联、Workday 等）一套适配器覆盖多家；探测不到的归入"仅存公告链接"层。

覆盖度分层，不追求所有企业都有岗位明细：

| 层级 | 可获得信息 | 代表 |
| --- | --- | --- |
| 有接口/可抓页面 | 岗位全明细，自动更新 | 腾讯、华为 |
| 通用 ATS | 岗位明细，一套适配器覆盖多家 | 使用 Moka/北森的企业 |
| 仅公告 | 企业名、标题、启动时间、公告链接 | 双胞胎集团（入口在图片内） |

## 理由

- 工作量从「数百套官网 selector」降为「10~20 套适配器」，因大厂自建接口有限、中型企业 ATS 高度集中。
- 接口返回结构化字段，不受官网前端改版影响，比 CSS selector 稳定。
- JSON 字段路径（如 `Data.Posts[3].RecruitPostName`）是天然且稳定的 locator，现有 `Evidence` 模型要求的"原文摘录 + 定位信息"在该路线下**更易满足**，无需改动证据模型的核心语义。
- `ApprovedApplicationHost` 模型在该路线下获得明确用途：微信官方公众号（`gh_` 号可验证）给出 `join.qq.com` → 该 host 获批 → 同域 `careers.tencent.com` 接口数据取得完整证据链。
- 原设计「每天 22:00 全自动更新」在岗位层完全成立。人工动作仅两处，且均为每家企业一次性：提供企业名单、抓包确定校招接口路径。日常运行零人工。

## 被否决的备选方案

- **仅采集微信公众号**：两篇样本正文纯图片、纯文本长度均为 0，岗位/地点/届别/截止/入口全在图片内，且腾讯样本根本未列岗位。需 OCR 或多模态识图，准确率不可保证并强制引入人工确认。**降级为兜底方案**，仅在企业既无接口又无结构化页面时考虑。
- **继续官网 HTML + 逐字段 CSS selector**：见背景第 1、2 条阻断。
- **教育部国家大学生就业服务平台作为官方聚合源**：岗位列表接口需登录，违反"不登录、不保存 Cookie"硬约束。
- **抓取聚合平台（BOSS 直聘、牛客、实习僧）**：非官方来源，违反项目边界；反爬严重。
- **在每日采集中普遍引入浏览器自动化（Playwright 等）渲染 SPA**：不采用。生产采集默认只使用普通 HTTP 请求。2026-08-27 的 ADR 0004 为中国联通增加了一个经用户单独批准的隔离浏览器例外；该例外不使用个人浏览器资料，也不自动扩展到其他来源。

## 本次决策同时确定的两项

- **放开城市限制**：原设计写死只显示北上广深。改为抓取并存储全量城市，前台提供城市筛选器。理由：腾讯 2278 个岗位含杭州、成都、武汉、西安等地；数据已抓取却不存储属于浪费，且日后调整范围无需重抓。
- **第一版不做微信模块**：初期企业名单（大厂 + 央企 + 500 强）足够支撑，省去一个模块的复杂度。微信层与岗位层解耦，可随时追加。首次实现时优先做"手动粘贴链接"，不做自动发现。

## 认知修正记录

- 用户原本设想「微信公众号锁定企业 → 再去官网找岗位」，实测后确认顺序应反转：官网接口为主，微信为补充。用户已确认该反转。
- 协调方最初判断「逐字段证据门控在此场景下是枷锁、需放宽」。该判断在识图路线下成立，在接口路线下不成立（JSON 路径即 locator），已更正，现有审计架构予以保留。
- 协调方最初依据单篇样本判断「微信正文均为图片」，样本量不足；第二篇样本印证后方确认，但仍不能推广为全部公众号文章的结论。
- 协调方曾以腾讯 `careers.tencent.com` 接口返回 2278 个岗位为据，宣称「腾讯校招已跑通」。经工作经验字段分布核查，该接口为社招池，结论错误，已更正。教训：取得任一招聘接口不等于取得校招数据，必须以岗位字段交叉验证。
- 协调方曾据可见文字长度判断华为为服务端渲染、可直接抓 HTML。实为未渲染的 Vue 模板占位符，结论错误，已更正。教训：可见文字长度不足以判断渲染方式，须检查文字内容本身。

## 待处理影响

- 新增配置驱动的 JSON 接口适配器，纳入 `radar/collectors/registry.py`。接入新企业应为「填一份配置」而非「写一段代码」：端点、请求方法、参数、分页方式、列表 JSON 路径、字段映射均由 `OfficialSource.parser_config` 承载。
- 每家企业接入前需完成一次浏览器抓包以确定校招接口路径，并记录为该来源的准入证据。
- 修正 `radar/collectors/html.py` 单岗位硬编码，支持一则公告多岗位。
- `Evidence.locator` 需容纳 JSON 字段路径形态（无需改语义，需在文档与校验中明确）。
- `OfficialSource.source_type` 需增加接口类来源取值；`adapter_name` 默认值 `html_selector` 需按来源形态设置。
- 城市筛选相关的表单、查询与前台控件调整。
- 国家电网类 HTTP 412 反爬来源的访问策略需单独评估，不得以伪装身份方式绕过。
