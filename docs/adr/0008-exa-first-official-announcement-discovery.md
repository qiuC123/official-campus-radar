# ADR 0008：官网与 ATS 公告候选采用 Exa-first 外部发现

状态：已接受

日期：2026-09-02

招聘雷达继续先回读已经准入的企业官网、公告源和 ATS；只有这些已知来源没有提供合格公告候选时，才进入外部候选发现。外部发现固定以 Exa API 为首选 Provider，Exa 对某个明确检索目标返回空结果、没有可路由候选、噪声或身份冲突占主导，或者发生允许降级的瞬时错误时，才按单企业调用 Codex CLI 扩展搜索。该决策用确定查询、资源上限和可观测错误取代 Codex 大批量 Prompt，但不预先声称 Exa 的召回率高于 Codex；生产默认切换仍取决于冻结基准集的 A/B 结果。

## Consequences

- 本轮 Exa 只发现官网和官方 ATS 候选，不搜索微信公众号；微信发现、文章回读、验证码、OCR、二维码和 Article/Media Evidence 继续属于 `wechat-oa`。Brave 不进入默认流程。
- 公告候选与检索观察分离：同一企业与规范 URL 只有一个候选实体，每次 Provider 返回都形成追加式检索观察。Provider 身份由适配器固定，不能接受模型自报来源。
- Exa 或 Codex 的标题提示、日期提示、摘要、排名和判断都是非证据元数据。摘要只在单次运行内用于排序，不进入公告证据；官网或 ATS 原文必须经过现有安全回读和来源准入后才能支持正式公告。
- 查询计划由企业名称、批准别名、显式招聘对象、招聘类型、日期窗口和已知域名确定生成，不根据当前年份猜测届次，也不调用模型规划查询。
- Exa 联网、Codex fallback、官网回读和候选写库使用独立授权。联网阶段不写数据库；显式记录时按企业串行、原子写入，单企业失败只使批次进入 `partial`。
- Exa Key 只在专用 HTTP 客户端中读取；Codex、`wechat-oa` 和浏览器子进程不得继承该凭据。客户端固定 HTTPS 主机与路径，禁用自动重定向、Cookie、`.netrc` 和隐式系统代理，并限制超时、重试和解压后响应大小。
- 旧 Candidate Batch schema v1 继续只读兼容，新输出使用能表达多条检索观察的 schema v2；旧候选和历史 JSON 不做破坏性迁移。
- Exa-only、Codex-only 和 Exa-first 加 Codex fallback 必须在同一人工冻结基准集上比较。组合方案的召回和官方候选精度不得低于 Codex-only，无证据候选误入正式数据必须为零；达到门槛后仍需人工确认才能切换生产默认。
