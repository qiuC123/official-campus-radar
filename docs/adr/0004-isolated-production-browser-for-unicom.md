# ADR 0004：中国联通采用专用隔离浏览器取得公开岗位 JSON

状态：已接受

日期：2026-08-27

影响范围：中国联通来源适配器、生产依赖、采集运行边界、T6 验收

## 背景

中国联通公开校招页 `https://zglt.zhaopin.com/scjobs/index.html` 在普通浏览器中可以匿名查看并翻页，但同一个公开接口通过独立 HTTP 请求调用时持续返回业务 `code=500`。T6 Cycle 04 已确认页面自身的第 2 页会返回不同岗位；干净的临时 Chromium 也能在不导入用户浏览器资料的情况下完成同样操作。

页面发出的请求默认每页 11 条，共约 246 页。受控实验确认：只把页面请求正文中的 `pageSize` 从 11 改成 100，保留页面自己产生的其余临时请求状态，公开页面仍能正常返回并翻页，可把单次采集降到约 28 页。实验没有读取或保存请求头、Cookie、令牌或个人浏览器资料。

ADR 0001 原先禁止 Playwright 进入每日采集。继续等待匿名 HTTP 恢复会使 25 个已准入来源长期停在 24 个发布完成，因此需要一个严格受限的例外。

## 决策

只为“中国联合网络通信集团有限公司”注册 `isolated_browser_json` 生产适配器。适配器必须：

- 每次运行启动全新的无头 Chromium context，结束后立即关闭；
- 不使用用户数据目录、`storage_state`、账号、Cookie 配置、代理、扩展或个人 Chrome/Edge；
- 只打开已核验的中国联通公开招聘页，只拦截已核验的智联岗位端点；
- 只核对公开请求正文，并只把 `pageSize: 11` 改成已批准的 `pageSize: 100`；请求范围、组织编号或分页顺序变化时立即失败；
- 不读取、记录或导出浏览器生成的请求头、Cookie、令牌；
- 按官方页面的“下一页”控件顺序翻页，页间至少等待 1 秒；
- 校验业务成功码、总数、页序、最大页数和岗位唯一键，任一异常都 fail-closed，不发布不完整岗位集；
- 将取得的 JSON 交给现有 `JsonApiSourceAdapter` 完成字段映射、证据、去重和正式发布。

该决定是 ADR 0001“生产采集只使用普通 HTTP”的单来源例外，不推翻 JSON API 仍是首选主形态的整体策略。其他企业若需要生产浏览器，必须重新取证、单独批准并新增 ADR，不能直接复用本适配器。

## Considered Options

- 继续等待匿名 API 恢复：最简单，但恢复时间未知，T6 无法闭环。
- 读取用户浏览器 Cookie 或复用个人浏览器：否决；会把个人凭据引入采集，无法审计和稳定复现。
- 每天点击页面 246 次：可行但访问次数和耗时过高。
- 干净浏览器把公开页面每页数量调整为 100：采用；不依赖个人会话，并显著降低请求次数。

## Consequences

- `playwright` 和 Chromium 运行时成为本机生产采集依赖，部署后需运行 `py -3.13 -m playwright install chromium`。
- 中国联通采集比普通 HTTP 慢约半分钟，并可能因页面控件或请求正文改变而安全失败。
- 失败只写运行记录，不删除既有批次、岗位或个人投递进度。
- T7 Windows 定时任务仍未获授权；本 ADR 只允许先完成中国联通单来源 T6 验收。
