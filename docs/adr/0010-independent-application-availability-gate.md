# ADR 0010：以独立可投递状态门控岗位库存

状态：已接受

日期：2026-09-03

## Context

美的日常实习的公开岗位接口仍返回 148 条岗位，项目接口也返回成功状态，但官方招聘页面已经显示“在招岗位（0）”和投递结束。此前采集流程只根据岗位接口库存发布批次，因此会把后端遗留记录误报为仍可申请。

岗位库存与当前可投递状态是两个不同事实。非空岗位数组、HTTP 200 或未说明语义的业务状态码，都不能替代用户在官方投递页面看到的当前开放状态。

## Decision

对存在这类风险且完成单独审核的来源，允许在来源配置中启用通用 `availability_probe`。它在岗位接口采集前，用全新、无持久化的无头浏览器读取同一官方来源 host 的页面正文，并只接受已配置的明确文本或岗位数量信号。

- 明确关闭：跳过岗位接口，发布带状态证据的撤回事件，将批次、岗位和投递链接退出当前展示。
- 明确开放：继续执行原岗位适配器；岗位数据仍须通过原有完整性与证据门控。
- 信号缺失、冲突、页面异常或后续岗位采集失败：记录来源失败，已启用状态探测的来源暂不进入正式列表，直到下一次完整成功。

探测配置必须使用 HTTPS 且与岗位来源完全同 host；禁止 URL 凭据、跨 host 重定向、批次共享配置和无限等待。浏览器不读取用户 profile、Cookie、登录态、代理或下载，不执行 OCR，不保存页面全文；数据库只保留规范状态、命中信号摘要、URL 和内容哈希。该机制按来源显式启用，不自动套用到全部企业。

## Consequences

- 用户可见的明确关闭状态优先于陈旧岗位库存，避免“接口仍有数据就显示招聘中”的误报。
- 模糊或失败时采用 fail-closed，会短暂隐藏无法重新确认的来源；这是有意选择的可信度优先策略。
- 页面文案或结构变化可能要求更新该来源的审核配置，但不能通过放宽为“只要接口有岗位就开放”解决。
- 美的日常实习是首个接入来源；其他来源必须先证明存在独立状态冲突风险，再单独配置和验收。

## Rejected alternatives

- 把非空岗位数组、HTTP 200 或项目接口 `status=1` 直接解释为开放：这些信号已经在美的案例中被证明可能陈旧。
- 依靠截图图像识别作为日常主路径：成本高、稳定性差，也难以形成可重复的结构化判定。
- 自动为所有来源开启浏览器探测：不同官网缺少统一状态语义，会增加网络成本和误判面。
