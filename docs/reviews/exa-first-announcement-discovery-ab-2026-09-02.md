# Exa-first 官网/ATS 公告候选发现 A/B（2026-09-02）

## 结论

本轮不通过生产默认切换门槛。Codex-only 在严格冻结 URL 和已知官方 host 两种口径上都优于 Exa-only 与实际运行的 Exa-first 组合；Exa-first 不能替换当前默认路径。迁移 `0035` 保持未应用，搜索结果没有写入业务数据库，也没有创建正式公告或招聘批次。

真实运行同时暴露并修复了三个实现缺陷：Windows 下 Codex 包装进程不能执行硬超时、企业主域的任意子域会被误认为已准入来源、Codex fallback 候选被追加到 Exa 噪声之后而没有重排。修复后只做保存结果的离线回放，不追加联网预算；回放仍低于 Codex-only，因此结论不变。

## 冻结范围

- 企业：腾讯、理想汽车、美的集团、OPPO、一汽-大众汽车有限公司、东风日产乘用车公司、中国中车集团有限公司、亚马逊中国、广汽丰田汽车有限公司、携程集团、网易、苹果中国。
- 显式条件：`2027届`、`秋招`、发布日期 `2026-06-01` 至 `2026-09-02`。
- 严格真值：运行评分前从已核验 `RecruitmentAnnouncement` 和已准入 `OfficialSource` 复制的 URL；完整清单见 `data/announcement-discovery-benchmark-v1.json`。
- 严格 URL 指标有意保守。搜索发现的其他同 host 页面只能进入“待安全回读/身份复核”，不能在本轮反向加入真值来抬高得分。
- 已知 host 指标只是候选发现代理指标，不是公告证据，也不能支持自动准入。

## 预算与执行事实

- Exa：48 次请求，达到硬预算；其中 2 次连通试跑、24 次 Exa-only、22 次组合组（腾讯复用 Exa-only 观察）。总费用约 `$0.280`。
- Codex：Codex-only 12 家各 1 次，组合组 3 家各 1 次，共 15 次，未重试失败公司。
- Exa-only 正式组按 8+4 两批运行，公司并发 2；24 次请求墙钟 35.6 秒。
- Codex-only 使用最多 2 个并行进程。10/12 成功；OPPO 超时，携程超时。旧包装层导致观察到 248.5 秒和 552.8 秒的失真超时，已修复为直接启动原生 `codex.exe`。
- 组合组墙钟 355.7 秒，3 家触发 Codex fallback，整批没有超过 10 分钟。
- 未运行 WeChat、Chrome 或可见浏览器；未调用官网 live fetch；未应用迁移；未记录搜索结果到数据库。

## 失败原因

1. Exa 中文校招查询噪声高。大量前排结果来自简历站、培训站、转载媒体、粉笔、知乎或 LinkedIn，域名限制查询也经常为空或仍返回宽泛主域内容。
2. 原路由把 `qq.com`、`163.com` 等企业主域的任意子域当成已准入来源，导致腾讯新闻和网易内容页被误判为合格候选。
3. 原组合合并保持 Exa 首次出现顺序，Codex 找到的官网/ATS 候选被排在 10–20 条 Exa 噪声之后，无法改善 recall@10。
4. Codex 结果更聚焦，但调用慢且存在超时；它适合受控 fallback，不适合无上限批量执行。
5. 冻结 URL 真值只覆盖仓库已核验身份，不能自动接受新项目参数、语言路径或桌面/移动入口等变体。这是安全限制，不是评分缺陷。

## 已实施整改与剩余门槛

- Windows 直接启动 Codex 原生可执行文件，避免只杀死 `cmd` 包装层；保留 180 秒单企业超时。
- 自动路由只接受精确匹配的已准入 host，不再因企业主域而接受任意子域。
- 候选按“确定性合格、已知来源身份、待审查、拒绝”重排，使 Codex 官方候选能越过 Exa 噪声。
- Codex attempt 记录真实耗时，并保留 `TIMEOUT` 稳定错误码。
- 仍需改进 Exa 查询计划、域名约束和候选质量，然后使用新冻结批次重新 A/B。当前结果明确禁止应用迁移或切换生产默认。
