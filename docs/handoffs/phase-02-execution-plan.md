## 各任务要点

### T1 · JSON 接口采集适配器

Prompt：`docs/handoffs/phase-02-01-json-api-adapter-prompt.md`

核心要求：端点、方法、请求体、分页方式、列表 JSON 路径、字段映射、业务成功码、HTML 富文本字段、校招过滤白名单，全部由 `OfficialSource.parser_config` 承载。接入新企业应为填配置而非写代码。JSON 字段路径直接充当 `Evidence.locator`。

### T2 · 接口发现工具

Prompt：`docs/handoffs/phase-02-02-api-discovery-tool-prompt.md`

**这是开发期工具，不是生产代码。** 必须隔离在 `tools/` 目录，不得被 `radar/` 下任何模块导入，playwright 不得写入 `requirements.txt`（另设 `requirements-dev.txt`）。生产采集只用 `requests`。

理由：接口路径无法静态获得（已在 ADR 中验证：SPA 脚本动态注入、CDN 对非浏览器请求返回空、猜测端点全部 404），但可通过监听浏览器实际发出的 XHR 得到。该工具把「每家人工 F12 抓包 3~5 分钟」变为批量自动化，人工仅需复核。

此为对 ADR 0001「不引入浏览器自动化」的**有限例外**：仅限一次性接口发现，不进入运行时采集路径。每个目标只能创建一个浏览器上下文和一个页面实例、执行一次初始导航；允许同页最多一次安全点击，禁止刷新、新窗口、弹窗和诊断性补跑。

### T3 · 批量探测

输入：`docs/source-inventory-2026-08.md` 的分层清单。

优先顺序：
1. 已确认在放校招岗位的企业（腾讯青云计划已于 2026-08-20 公告「网申通道已开启」）
2. 宁德时代 `talent.catl.com`（疑似直连 Moka，用于验证「一套 ATS 适配器覆盖多家」的假设——携程已证实为自建接口层包装 Moka，无法验证该假设）
3. 大疆 `careers.dji.com`（线索最明确）
4. 其余大厂

**探测纪律（必须遵守）**：

- 每个站点低频访问，请求间有延时，不并发轰炸单一站点。
- 每个目标只运行一次：一个浏览器上下文、一个页面实例、一次初始导航、零刷新；允许同页最多一次安全点击。单个标准化端点在整个验收周期内累计重放不超过 6 次，不能靠重新运行进程重置预算。
- 不登录、不绕过验证码、不使用代理池、不逆向签名算法。若某站点必须携带前端生成的签名才能调用，判为不可接入，归入「仅存公告链接」层，**不得尝试破解**。
- 探测到的端点须验证「去掉签名头与 Cookie 后是否仍可调用」（携程实测两者均非必需），只有合规可调用的才纳入接入清单。

**验证纪律（本项目已三次因此下错结论，必须执行）**：

先验证数据性质，再看数量。取得端点后须逐项确认：

1. 校招判别字段（如 `kindName` / `RequireWorkYearsName`）的取值分布；
2. 抽样 10 条岗位标题，人工可读地判断是否符合校招特征（出现「资深」「Senior」「N 年以上工作经验」即为社招信号）；
3. 岗位身份键非空且唯一；
4. 分页正确（第 2 页内容与第 1 页不同）。

四项全过才算探测成功。数量增长本身不是成功证据。

### T4 · 来源准入落库

把 T3 的配置草案变成数据库中的 `Organization` + `OfficialSource`，并走完准入链（候选 → 已核验 → 已启用），每步写 `SourceAdmissionEvent`（append-only、带哈希链）。准入证据记录：官方招聘站点 URL、接口端点、以及（若有）微信官方公众号文章作为官方性佐证。

不得跳过准入链直接把来源置为 enabled。

### T5 · 放开城市限制 + 前台改造

现设计写死只显示北上广深，改为抓取存储全量城市、前台提供筛选器。前台改造参考「来个 OC」形态：统计条、多岗位聚合展示、列显示/收起、多值筛选。

### T6 · 首次真实采集与验收

验收须证明：真实岗位入库且通过三重证据门控显示在页面上、重复运行不产生重复记录、岗位下线进入历史而非物理删除、个人投递进度可保存且不被采集覆盖。
