# Phase 02 产品需求：前端优先的校招岗位工作台

状态：Implementation baseline

日期：2026-08-26

## 1. 用户和目标

唯一用户是项目所有者。页面首先帮助用户快速发现值得投递的官方校招岗位，其次帮助用户记录每个岗位的投递状态。

成功条件：在 Windows 桌面浏览器中，用户可以按公司、招聘类型、对象、城市、岗位、进度和截止时间找到岗位；同一招聘批次的不同岗位可以保存不同进度；页面能区分岗位真实变化、每日例行核验和历史下线。

## 2. 产品结构

- 首页只展示招聘中的批次，历史页展示已截止或已撤回批次。
- 一个招聘批次属于一家公司和一个招聘类型，可包含多个招聘岗位。
- 每个批次先展示最近变化的 3 个岗位，可展开全部。
- 岗位职责和要求在当前页面行内展开。
- 岗位进度使用七种状态：未投递、已投递、已笔试、已面试、未通过、面试通过、暂不投递。
- 历史岗位仍允许修改个人投递进度。

## 3. 筛选和排序

筛选器：公司关键词、公司类型、行业、招聘类型、招聘对象、多城市、岗位关键词、多选投递进度、截止日期。跨筛选器使用 AND，同一多选筛选器内部使用 OR。

默认按岗位有效更新时间倒序；有效更新时间来自官网更新时间或系统检测到的真实内容变化，例行核验不算更新。选择任何具体城市时仍保留“全国”和“远程”岗位。

每页显示 20 个招聘批次，筛选和页码保留在 URL 中。

## 4. 首页信息

顶部统计随当前筛选变化：

1. 招聘中的岗位数量；
2. 近 3 天首次发现或真实变化的岗位数量；
3. 未来 7 天内截止的岗位数量；
4. 已投递、已笔试或已面试的岗位数量。

批次固定展示公司、批次名称和岗位列表。岗位标题、城市、投递进度和投递入口不可隐藏；公司类型、行业、招聘类型、招聘对象、更新时间、截止时间和官方招聘页可以隐藏，选择保存在浏览器本地。

## 5. 空状态和失败状态

- 正式数据库为空时显示“尚无已准入的真实校招岗位”，不得显示演示数据冒充真实数据。
- 截止时间未知时显示“未说明”，不计入临近截止统计。
- 岗位没有直投链接时回退到批次官方招聘页，并明确标注。
- 自动保存失败时恢复原状态并显示错误，不允许界面看似成功而数据库未保存。
- 预览页必须标注“模拟数据，不是线上岗位”，更新按钮禁用。

## 6. 范围边界

继续使用 Django 服务端页面和少量原生 JavaScript。不增加 React/Vue、账号、多用户、公司规模、社区笔试信息、自动投递、真实来源探测、Windows 任务注册、微信模块或云部署。

## 7. 验收场景

- 一个批次包含 5 个岗位，默认显示 3 个，展开后显示全部。
- 同批次两个岗位分别保存“已投递”和“暂不投递”。
- 同时筛选上海和杭州，全国/远程岗位仍出现。
- 岗位内容无变化的每日核验不会把它排到最前。
- 已撤回岗位在历史页可见，个人进度仍能更新。
- 预览页可切换正常、漏跑和来源失败三种运维视觉状态，但不会执行更新。
