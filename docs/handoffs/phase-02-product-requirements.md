# Phase 02 产品需求：前端优先的校招岗位工作台

状态：H1 Prototype Cycle 02 candidate

日期：2026-08-26

## 1. 用户和目标

唯一用户是项目所有者。首页首先帮助用户按企业属性、行业和毕业届次快速发现值得进一步查看的官方招聘批次。

成功条件：在 Windows 桌面浏览器中，用户可以按公司、公司类型、行业、招聘类型、毕业届次、城市、岗位关键词和截止时间找到招聘批次；每个批次只展示少量代表岗位，页面能区分岗位真实变化、每日例行核验和历史下线。

## 2. 产品结构

- 首页只展示招聘中的批次，历史页展示已截止或已撤回批次。
- 一个招聘批次属于一家公司和一个招聘类型，可包含多个招聘岗位。
- 每个批次最多展示 5 个代表岗位名称，并显示匹配岗位总数与主要工作地点。
- 首页不展开岗位职责，不为每个具体岗位展示或修改投递进度。
- 本 Cycle 不把岗位级进度改成公司级或批次级进度；已有岗位级数据语义保持不变，是否另做进度管理页以后再决定。
- 公司类型按企业属性划分为民企、国企、外企和其他；“互联网/科技”等只能放入所属行业。
- 当前年份为 2026 年，招聘对象列出上下两届：2024届、2025届、2026届、2027届、2028届；实习岗位统一使用“实习生”，不用“在校生”。

## 3. 筛选和排序

筛选器：公司关键词、公司类型、所属行业、招聘类型、招聘对象、多城市、岗位关键词和截止日期。跨筛选器使用 AND，同一多选筛选器内部使用 OR。

默认按岗位有效更新时间倒序；有效更新时间来自官网更新时间或系统检测到的真实内容变化，例行核验不算更新。选择任何具体城市时仍保留“全国”和“远程”岗位。

每页显示 20 个招聘批次，筛选和页码保留在 URL 中。

## 4. 首页信息

顶部统计随当前筛选变化：

1. 招聘中的岗位数量；
2. 近 3 天首次发现或真实变化的岗位数量；
3. 未来 7 天内截止的岗位数量；
4. 当前筛选结果覆盖的公司数量。

批次固定展示公司、批次名称、代表岗位和主要工作地点。公司类型、行业、招聘类型、招聘对象、更新时间、截止时间和官方招聘页可以隐藏，选择保存在浏览器本地。首页只提供批次官方招聘页，不在代表岗位上逐个放置投递入口。

## 5. 空状态和失败状态

- 正式数据库为空时显示“尚无已准入的真实校招岗位”，不得显示演示数据冒充真实数据。
- 截止时间未知时显示“未说明”，不计入临近截止统计。
- 岗位没有直投链接时仍可通过批次官方招聘页继续查看，不虚构岗位直投入口。
- 预览页必须标注“模拟数据，不是线上岗位”，更新按钮禁用。

## 6. 范围边界

继续使用 Django 服务端页面和少量原生 JavaScript。不增加 React/Vue、账号、多用户、公司规模、社区笔试信息、自动投递、真实来源探测、Windows 任务注册、微信模块或云部署。

## 7. 验收场景

- 一个批次包含 7 个岗位，首页只显示前 5 个代表岗位并提示其余数量。
- 公司类型只出现民企、国企、外企或其他；互联网/科技只出现在所属行业。
- 招聘对象可以分别筛选 2024届至2028届和实习生，不出现合并届次或“在校生”。
- 首页不出现岗位级投递进度筛选、下拉框或求职进度统计。
- 同时筛选上海和杭州，全国/远程岗位仍出现。
- 岗位内容无变化的每日核验不会把它排到最前。
- 已截止或撤回的批次在历史页可见。
- 预览页可切换正常、漏跑和来源失败三种运维视觉状态，但不会执行更新。
