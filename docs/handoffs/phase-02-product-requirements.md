# Phase 02 产品需求：前端优先的校招岗位工作台

状态：H1 passed / H2 pending

日期：2026-08-26

## 1. 用户和目标

唯一用户是项目所有者。首页首先帮助用户按企业属性、行业和毕业届次快速发现值得进一步查看的官方招聘批次。

页面允许普通访问者浏览和筛选招聘信息；项目所有者以管理员身份查看采集运行状态、失败信息和人工更新入口。管理员运维信息不得出现在普通访问者页面中。

成功条件：在 Windows 桌面浏览器中，用户可以按公司、公司类型、行业、招聘类型、毕业届次、城市、岗位关键词和截止时间找到招聘批次；每个批次只展示少量代表岗位，页面能区分岗位真实变化、每日例行核验和历史下线。

## 2. 产品结构

- 首页只展示招聘中的批次，历史页展示已截止或已撤回批次。
- 一个招聘批次属于一家公司和一个招聘类型，可包含多个招聘岗位。
- 首页采用高密度横向表格，一个招聘批次占一行。
- 每个批次最多展示 5 个代表岗位名称，并显示匹配岗位总数与主要工作地点；不展开岗位职责。
- 首页不为每个具体岗位分别展示进度，只在批次行保留一个投递进度下拉框。
- 投递进度归属于招聘批次，由用户手动维护；系统不根据岗位数量、岗位状态或最远阶段自动计算。
- 公司类型按企业或机构性质划分为央国企、民企、事业单位、银行、外资、中外合资和社会机构；外资与中外合资必须独立展示和筛选，“互联网/科技”等只能放入所属行业。
- 招聘类型按招聘阶段划分为春招、秋招、秋招补录、秋招提前批、实习和春招补录。
- 当前年份为 2026 年，招聘对象列出上下两届：2024届、2025届、2026届、2027届、2028届；实习岗位统一使用“实习生”，不用“在校生”。

## 3. 筛选和排序

筛选器：公司名称、公司类型、地点、招聘类型、招聘对象、岗位、批次行投递进度和截止时间。公司类型、招聘类型和投递进度采用复选弹层；地点采用省份复选弹层，最多选择 5 个。岗位使用逗号输入多个条件。跨类别使用 AND，同一多选类别内部使用 OR。所属行业保留为结果列，不放入紧凑筛选区。

默认按岗位有效更新时间倒序；有效更新时间来自官网更新时间或系统检测到的真实内容变化，例行核验不算更新。选择任何具体城市时仍保留“全国”和“远程”岗位。

每页显示 20 个招聘批次，筛选和页码保留在 URL 中。

## 4. 首页信息

筛选区下方的蓝色汇总条随当前结果变化：

1. 今日更新的企业数量；
2. 近 3 天更新的企业数量；
3. 1 天内截止的企业数量；
4. 3 天内截止的企业数量。

表格固定展示公司名称、公司类型、所属行业、招聘类型、招聘对象、工作地点、代表岗位、批次行投递进度、更新时间、投递截止、相关链接和批次官网。桌面窄于表格最小宽度时主动提供横向滚动，不自动隐藏已确认列。代表岗位不逐个放置投递入口，点击代表岗位区域可展开该批次的全部岗位。

## 5. 空状态和失败状态

- 正式数据库为空时显示“尚无已准入的真实校招岗位”，不得显示演示数据冒充真实数据。
- 截止时间未知时显示“未说明”，不计入临近截止统计。
- “招满为止”只在官方来源明确提供该含义时显示，不得用它代替未知截止时间。
- 岗位没有直投链接时仍可通过批次官方招聘页继续查看，不虚构岗位直投入口。
- 预览页必须标注“模拟数据，不是线上岗位”，更新按钮禁用。
- 运行状态、最近成功更新时间、失败信息和人工更新入口仅管理员可见，并同时在服务端校验权限，不能只依赖前端隐藏。

## 6. 范围边界

继续使用 Django 服务端页面和少量原生 JavaScript。不增加 React/Vue、普通用户账号体系、多用户业务功能、公司规模、社区笔试信息、自动投递、真实来源探测、Windows 任务注册、微信模块或云部署。管理员身份复用现有 Django 管理员账号。

## 7. 验收场景

- 一个批次包含 7 个岗位，首页只显示前 5 个代表岗位并提示其余数量。
- 公司类型只出现央国企、民企、事业单位、银行、外资、中外合资或社会机构；外资与中外合资不得合并，互联网/科技只出现在所属行业。
- 招聘对象可以分别筛选 2024届至2028届和实习生，不出现合并届次或“在校生”。
- 首页不出现逐岗位投递进度；每个招聘批次只出现一个行级下拉框，并由用户自行决定该批次的当前状态。
- 一个招聘批次必须只占一行，列顺序与 Cycle 03 参考表格一致。
- 筛选区采用两行紧凑控件，查询、重置和蓝色汇总条紧邻排列，不再使用四张大统计卡片。
- 公司类型、招聘类型和投递进度可勾选多个；地点可勾选最多 5 个省份，超过上限时不接受第 6 个。
- 同时筛选上海和杭州，全国/远程岗位仍出现。
- 岗位内容无变化的每日核验不会把它排到最前。
- 已截止或撤回的批次在历史页可见。
- 预览页可切换正常、漏跑和来源失败三种运维视觉状态，但不会执行更新。
- 普通访问者看不到整个运维区域；管理员可以看到运行状态和人工更新入口。直接请求更新接口时仍必须通过管理员权限校验。
