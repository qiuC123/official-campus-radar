## Cycle 规则

- 50 家企业全部尝试，不以空白代替失败。
- 只访问公开页面和企业官网直接链接的第三方招聘系统。
- 浏览器目标串行执行，目标之间至少间隔 3 秒，不进行同域并发。
- 不登录、注册、投递、填写表单或个人信息，不接受凭据。
- 不绕过验证码、访问控制、限流或风控；遇到上述情况立即停止该企业并记录。
- 不设置“每家公司只能打开一个页面”的硬上限。一个目标条目仍只访问一次；如确需同一企业的另一个官方入口，必须登记新的目标 ID、访问理由和所属 Cycle。
- 不为了改善结果而重复运行本 Cycle 中已经失败的目标。修正入口或工具后必须进入新的 Cycle，旧失败记录不得覆盖。
- 相同规范化端点在一次运行内共享最多 6 次重放预算；只有一个安全变体执行完整五级重放梯度。

## “可稳定接入”人工判定

只有同时满足以下五项，企业才计入 H3 最低成功线：

1. 来源属于企业官网或有企业官网直链证据；
2. 最简合规请求头可返回等效、非空的岗位列表；
3. 原始字段能够判别校招或实习范围；
4. 岗位标题和地点均可取得；
5. 分页规则明确且可配置。

工具显示“可接入”只证明第 2 项，不自动等于“可稳定接入”。

## 失败分类与下一 Cycle 建议

1. **入口可访问但没有候选（22 家）**：优先核对是否存在更直接的公开岗位列表页；只有官网可证明的新入口才能进入下一 Cycle。
2. **页面跳过/访问失败（9 家）**：保持不规避。可尝试企业官网公开的另一入口或静态公告方案，但不得忽略证书、绕过 412 或伪装浏览器。
3. **非岗位误报（9 家）**：收紧候选数组启发式，至少要求同一行同时存在可用标题和地点，排除内容树、语言表、车型、资讯和客服数据。
4. **真实岗位请求但最简头/签名失败（4 家）**：保持不可接入，不逆向签名；除非企业另有公开无签名入口，否则不建议重复探测。
5. **岗位数据但范围/字段/分页不足（4 家）**：为腾讯、亚马逊等设计明确的校招/实习筛选入口；美团需要补岗位详情或正确标题字段；证据不足前不计成功。

下一 Cycle 必须由用户确认后再启动。建议范围只包含有新官方入口或可离线修复误报规则的企业，不重放本 Cycle 已消耗预算的相同规范化端点。
