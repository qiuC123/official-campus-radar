## 安全拒绝

拒绝没有写入招聘批次或岗位，只追加不可变的 PublicationEvent。原因计数允许同一家同时命中多个原因：

| 原因 | 次数 | 含义 |
| --- | ---: | --- |
| `incomplete_field_evidence` | 13 | 至少一个批次或岗位字段缺少可核对证据 |
| `not_eligible_recruitment_type` | 11 | 当前分类器未确认校招/实习语义 |
| `incomplete_position_coverage` | 1 | 分页没有证明覆盖全部岗位 |
| `conflicting_position_identity` | 1 | 同一来源返回重复岗位唯一键 |

已确认的实现问题：批次配置已经明确给出 `campus_recruitment` / `internship` 时，当前发布器仍把所有岗位标题一起重新分类；只要其中一个岗位含“招标”等词，就可能把整个校招批次误判为其他招聘。该问题在独立修复 Cycle 处理，本 Cycle 不边采边改。

另一个重试阻断是：当前更新器会把“抓取成功但发布被拒绝”的 SourceVersion 标成已应用；如果官网响应内容哈希没有变化，普通重试会直接判为 `unchanged`，无法让修复后的发布逻辑重新处理。Cycle 02 必须先提供受控的拒绝版本重处理机制，且保留原拒绝事件，不能直接改数据库历史。
